# 研发交接

## 当前主分支状态

`main` 已合入 XAML、异步 libmpv 核心、拥有型交换链桥接、播放列表、轨道和字幕、设置与历史，以及原生窗口集成。真实播放依赖固定源码和私有补丁构建的 libmpv。当前验证见 [VALIDATION.md](VALIDATION.md)。IINA 插件及扩展机制不纳入移植范围。

本地 Debug 和 Release x64 构建、Release 启动关闭均已通过。下一步按 [LIBMPV.md](LIBMPV.md) 准备 SDK，执行阶段 B 的真实播放和视频合成验收。

## 接手入口

先读根目录 [AGENTS.md](../AGENTS.md)，再读 [ARCHITECTURE.md](ARCHITECTURE.md)。以当前检出目录为仓库根目录，远程为 `https://github.com/helloktz/IIMA`。

本地 Windows 构建、打包和启动关闭检查入口见 [BUILD.md](BUILD.md)。参考源码已随仓库检出。

IIMA 是基于 IINA 开源源码的 Windows 移植。`references/iina/` 是设计与实现的直接依据，适用的上游逻辑可以直接复用或转写。首次接入 libmpv 时就按这个方式工作，沿用 IINA 的播放协调、状态和事件语义，并用 Windows 原生接口替换平台部分。

## 开发环境与分批交付

- 在 Windows 研发环境按 [BUILD.md](BUILD.md) 执行构建和适用的检查。涉及播放、窗口或硬件行为时，在具备相应依赖和设备的环境验证，缺失的运行证据写入 [VALIDATION.md](VALIDATION.md)。
- 下文的阶段完成条件用于验收。区分已实现、已验证和待验证的内容，列出需要在 Windows 上执行的构建和运行检查。
- 按功能将完整、可审阅的改动分批 commit，并适时 push 到本仓库的独立开发分支。暂时无法在 Windows 上构建或运行时，仍可提交和推送，在汇报中标明验证限制。如果推送受阻，保留本地提交并报告具体原因。开发分支的提交和推送已获授权，合并到 `main` 和发布版本需另行授权。

## 实施顺序与完成条件

### 阶段 A：Windows 构建基线

固定工具链下的 Debug/Release x64、MIDL/XAML 生成和 Release 启动关闭已验证。构建命令和结果见 [BUILD.md](BUILD.md) 与 [VALIDATION.md](VALIDATION.md)。

### 阶段 B：打通 libmpv 与视频合成

- 获取或按上游支持的方式构建明确版本的 x64 libmpv，记录来源、构建选项、头文件及导入库配套关系。
- 从 IINA 的 `PlayerCore.openURLs`、`MPVController.handleEvent` 和 `PlaybackInfo` 入手，追踪打开文件、异步事件、状态更新与关闭释放。用实际调用链确定最小移植范围，并标出需适配 Windows 的窗口和渲染职责。
- 实现 MpvClient、最小 PlayerSession、VideoPresenter 与一个简单控制栏。
- 实际验证 gpu-next + D3D11 composition + SwapChainPanel；选项存在、交换链创建、尺寸更新、失效和解绑均需确认。
- 完成打开文件、暂停/继续、seek、换片、错误提示和关闭释放链路。

完成条件：能播放有声音的视频；XAML 控件能在视频上操作；连续缩放与全屏切换可用；快速换片及关闭不崩溃、不留下进程；日志能确认实际渲染与解码路径。未获验证的 HDR 等能力单列，不包装为已完成。

若合成方案受阻，保存复现步骤和明确原因，更新架构中的呈现决策。保持其他模块边界，避免边试验边重写整个应用。

### 阶段 C：按 IINA 功能链迁移

逐项从 IINA 的入口追踪到实现，读清正常路径、默认值和边界行为。优先转写可复用的逻辑，按 Windows 的窗口、输入和系统能力适配平台部分。验收时对照源代码确认可观察行为，并说明每处有意差异。

- 播放列表：加入、移除、排序、上一项/下一项及当前项同步。
- 音轨、字幕、章节、倍速、音量与截图。
- 快捷键、菜单与控制栏使用同一命令入口。
- 设置、播放历史和续播。
- 拖放、外部文件打开、窗口尺寸与全屏行为。

完成条件：每项有源文件/符号对应和 Windows 差异说明；界面操作真实生效，状态可反映播放器变化。采用有代表性的行为测试，不以按钮存在或 mock 数据作为功能完成证据。

为实际迁移项维护 `docs/PORTING.md`，列出：功能、上游符号、目标实现、已保留行为、差异、验证。开始迁移时创建，不预填虚假的完成状态。

### 阶段 D：Windows 集成与体验打磨

- 系统媒体控制、防休眠、文件关联与实例激活。
- 焦点、键盘导航、可访问性、中文路径和错误恢复。
- HDR/SDR、多 DPI/刷新率显示器、音频设备切换及睡眠恢复。
- 大播放列表、未知时长媒体和加载失败等受支持场景。

完成条件：验证记录说明 Windows build、相关硬件、依赖版本与结果。无硬件的项目标为未验证；不得只用一个本机样例推广全部硬件兼容性。

### 阶段 E：交付可分发应用

- 在未安装开发工具的 Windows 11 x64 环境验证 Release 产物及依赖完整性。
- 整理正式构建与打包命令、使用说明、许可与来源材料。
- 根据实际发行方式落实安装器、签名和更新方案。

完成条件：完整分发目录/包可独立部署运行，不依赖研发机器 PATH 或未打包 DLL；安装与卸载（如采用安装器）得到验证；已知限制如实记录。

## 验证与汇报

- 每个阶段只补充能解决当前不确定性的测试。纯逻辑优先用输入输出对照，窗口和图形问题使用实际运行验证。
- 记录执行过的命令、结果、运行环境与尚未验证事项。避免重复测试已确认且未受变更影响的功能。
- 交付时列出真实代码变更、完成的功能、检查结果和阻断点；不以文档、接口或编译成功替代产品完成度。
- 每个里程碑汇报开发分支、最新提交、已推送的改动和待验证事项。
